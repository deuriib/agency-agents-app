# 261103_antigravity-app-detection

## Objective

Issue #69. Antigravity ships as three surfaces — the App, the CLI and the IDE —
and the detection list covered only two, so a user who runs just the desktop app
read as "not installed": absent from the Tools view, missing from the deploy
pickers, and undercounted in the roster ("CLI + IDE" instead of
"CLI + IDE + App").

## Outcome

- ✅ `.gemini/antigravity` joins `.gemini/antigravity-cli` and
  `.gemini/antigravity-ide` in `detect.dirs`, so any surface detects the tool.
- ✅ The change lives in `src-tauri/data/tools-overlay.json` — the sanctioned
  place to disagree with upstream (issue #72) — with a `_why` that names the
  three surfaces. `src-tauri/data/tools.json` stays generated, so the Rust
  registry and `src/lib/data/toolRegistry.ts` both pick it up from one file.
- ✅ `agentsDir` is untouched (`.gemini/config/agents`): detection is not a
  destination guess, and widening it would write agents where the app does not
  read them.
- ✅ Three tests on the real `detect` path:
  - any one of the three surfaces detects Antigravity, with the same `agentsDir`
  - all three together still report the tool once
  - a home with only `.gemini` (Gemini CLI's) does not detect Antigravity

## Files

- `src-tauri/data/tools-overlay.json` — the override + its reason
- `src-tauri/data/tools.json` — regenerated by `mise run sync-vendor`
- `src-tauri/src/install/mod.rs` — the three detection tests

## Non-changes (deliberate)

- **No new tool, no doc-table change**: `scripts/check-doc-tools.mjs` still
  reports 13 badges and 13 README rows, which is the proof that detection was
  widened without advertising a new integration.
- **No `agentsDir` change**: the issue warns that a wrong guess would write
  agents where the app never reads them; verifying that needs a machine with the
  app installed, so it stays out.
- The rule harness contract is untouched — it is a separate `agency-rules`
  contract with its own user scope (`~/.gemini/config/rules/`).

## Follow-ups

- Nothing pending. When the overlay next needs a detection root for another
  surface, it is one line here, and the overlay rejects an entry that stops
  differing from upstream so stale overrides cannot accumulate.
